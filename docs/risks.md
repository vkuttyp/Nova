# Technical Risk Register

Status: Milestone 0 / C0 (master prompt §23.J and CosmoOS deliverable 9). Ranked by
(likelihood × impact on safety). Reviewed at the end of every milestone.

| ID | Risk | L | I | Mitigation | Detection | Owner milestone |
|---|---|---|---|---|---|---|
| **R-1** | **Borrow-checker unsoundness.** NLL region solving, two-phase borrows, reborrows and partial moves are subtle. One hole silently breaks the safety guarantee (Goose's own lifetime checker had about half of recent commits fixing holes: `research/goose.md` §9.4) | High | Critical | Keep v0 intraprocedural and small (E1–E4). Specify every rule in `ownership.md` before implementing it. Use a separate init check and borrow check. "Checker as validator" re-runs on optimised NIR | Compile-fail corpus (≥ 2 tests per rule; M6d adds a vector-invalidation suite, and closes two growable-buffer hazards in lowering: `for` over a vector holds a view loan, and an element write after a call re-checks its index; M6e fixed a liveness hole that made the checker over-strict, not unsound: `Unpack` targets were not definitions; M6x adds writes into aggregates and through references, signature flows and a drop check, each with compile-fail tests and a model-based property test), mutation-generated negatives with independently computed verdicts, ASan/UBSan on all run-pass output, the random program generator (M7d; its first runs found a false N0272: a Copy value read through a `borrow mut` parameter was treated as carrying the parameter's loans), the NIR reference interpreter (M7c) as a dynamic oracle for liveness, bounds and initialisation on every run program and sweep point; borrow tracking (Stacked-Borrows-style) is not done. M8a adds `unsafe`: raw pointers carry no loans (U3), and references made from them are unconstrained, so a wrong `Safety:` argument is unsound without any diagnostic. Containment: only the U1 operations need `unsafe` (N0280, compile-fail corpus), every unsafe function states its contract (N0283), safe code is checked exactly as before, and the interpreter faults on invalid accesses through pointers (`UnsafeTests`) | M2, M7, M8 |
| **R-2** | **Unsafe/FFI contract errors.** C libraries and kernel APIs do not follow Nova ownership. Unbounded regions from raw→ref conversions (U3). Wrong effect declarations in binding files | High | Critical | All `extern` calls are `unsafe`. Safe wrappers carry `/// Safety:` contracts. Binding files are reviewed and default to the most conservative effects. Raw→ref conversion is only possible through APIs that bound the region by signature | Lint for missing contracts. Wrapper unit tests under ASan. Kernel: lockdep and `might_sleep` stay on in debug. **C3:** the I/O runtime (`nova_rt_io.c`), the first binding with OS semantics, runs against CosmoOS's own libc in the guest (`c3.py`), including its non-POSIX `sockaddr`, spawn API and wait status; known gap: CosmoOS has no `MSG_NOSIGNAL`/`setsockopt`, so a socket write to a closed peer may raise `SIGPIPE` there. **M8a:** the `Safety:` lint is N0283, and the interpreter faults on invalid accesses through pointers (`UnsafeTests`). **M8b:** C prototypes use C's own types, `@repr` enum values from C are checked, and `FfiTests` runs C→Nova and Nova→C under ASan+UBSan. **M8c:** a freestanding object's undefined symbols are an allowlist, so nothing hosted leaks into a kernel build (`FreestandingTests`). **C4/C5:** Nova objects meet the module loader's rules (`c4.py`), and Nova code allocating from `kmalloc` passes an in-kernel selftest with an injected-failure sweep and no leaked blocks (`c5.py`); `KernelHeap` refuses alignments `kmalloc` does not give. **C7c:** lock bindings keep their data private to their file (type-system §12), so safe code reaches it only through a guard; a guard that failed to unlock is caught by the host test | M8, C5, C7 |
| **R-3** | **Undefined behaviour in generated C.** Signed overflow, shifts, evaluation order, aliasing, side-effect-free loops, implicit promotions of narrow types. clang and gcc optimise UB differently | Medium | Critical | Checklist in `c-backend.md` §5, enforced by construction (NIR sequencing, helpers). No reliance on `-fno-strict-aliasing` | Differential testing (clang × gcc × O0/O2), UBSan, the random program generator (M7d: it found a C name collision with the runtime and four kinds of warnings on valid programs, all fixed; the M7e 24-hour campaign, 423,773 programs through clang and GCC at `-O0`/`-O2`, found no miscompile and one more warning kind, fixed), golden C review. M7b's structured form keeps an invariant (every block ends in an explicit transfer) and is checked against the flat form in its own run configuration on the whole run corpus. M8a's raw pointers emit no C pointer arithmetic and no pointer-to-pointer casts (all through `uintptr_t`, `unsafe.md` §4); the pointer corpus runs under ASan+UBSan. M8b: C prototypes use C's own types, because a call through an incompatible prototype is undefined (C11 6.5.2.2) even where the ABI agrees; `@repr` enum values from C are checked | M1→M8 |
| **R-4** | **Host leakage into target layout/semantics.** .NET `sizeof`/`Marshal` used for layout; `char` signedness; endianness assumptions | Medium | High | `TargetInfo` is the only layout source. Banned-API analyzer. `_Static_assert(sizeof/offsetof)` in all generated C, except for types that hold C state, which have only the C compiler's layout (type-system §33.1): Nova computes no layout for them at all, and the interpreter faults instead of guessing one. Nova never uses C `char` | Static asserts fail the C build. Cross-compile tests for both CosmoOS triples in M1 | M1 |
| **R-5** | **Kernel context-effect unsoundness.** Atomic/sleepable is a runtime property in CosmoOS. Indirect calls, callbacks and wrong binding annotations can let sleeping code run under a spinlock or quiesce guard | Medium | Critical (deadlock, RCU violation) | Conservative defaults (`sleep+alloc` for externs without `@effects` and for C function-pointer calls). Effects inferred over the package, drops included, and checked in `@context` functions and wherever an `@context(atomic)` value (a spin guard) may be live (C7a, type-system §32). CosmoOS's own `might_sleep()` in every sleeping primitive stays the runtime backstop (Nova emits none: its debug half is not exported to modules). Never claim effects prove kernel concurrency properties | Kernel debug builds with lockdep. Negative effect tests (`check-fail/effects.nova`, 13 cases, C7a; `c7/negative/`, sleeping under CosmoOS's own spin guards, C7c). QEMU stress tests (C7) | C7 |
| **R-6** | **Kernel object lifetime and quiescence misuse.** `kobject_put` with a blocking release under a spinlock (unchecked in CosmoOS today). Guard-scoped borrows escaping. Callbacks outliving module unload. No `call_quiesce` barrier | Medium | Critical | `KRef` drop has the `sleep` effect. Guard-scoped borrows (R4). Registrations are owned values torn down by generated `shutdown()`. `deferDrop` forbidden in modules until KQ-3 | Unload stress tests in QEMU (C8). Zombie-module detection. Lockdep  **C7d:** `KRef<T>` drop is `kobject_put` with the `sleep` effect, so a final put under a spin guard does not compile; `deferDrop` is `unsafe` with the KQ-3 contract (unload does not wait for `call_quiesce`); release runs once, at the last put, against CosmoOS's own `object.c` (host test) | C5–C8 |
| **R-7** | **Drop elaboration and error-path bugs.** Double drop or missed drop on `?` paths, partial moves, early returns, loops. Allocation-failure paths are never exercised | Medium | High | Drop flags are derived from the same init analysis as move checking. `FailingAllocator` fault injection in every heap test | Run-pass tests with drop-counting types. Fault-injection sweeps (fail the k-th allocation for every k). ASan leak and double-free detection. **Status (M3b):** the sweep runs on every allocating run-pass program, with the runtime's live-allocation count as the leak check (LeakSanitizer is unavailable on macOS). M3a found and fixed two missed-drop bugs from M2: discarded call results, and statement temporaries on early exits. **M6c:** a lowering that returned "never completes" while its block was still open silently dropped a statement; the NIR builder now treats that as an internal error | M2, M3 |
| **R-8** | **Optimisation changes semantics.** Placement analysis, move elimination or BCE changing destruction order, allocator observability or bounds behaviour | Medium | High | Placement rules in `memory-model.md` §5 (allocator must be placement-transparent; KernelHeap never is). Each optimisation has written preconditions. Checker re-run on optimised NIR | Optimisation on/off equivalence tests, fuzz-differential on BCE (as Goose does), `--explain-allocations` snapshots. M5 (done): placement off/on gives equal outputs and identical drop traces on every run program, native and interpreter agree with placement, and a fuzz configuration builds with placement | M5, M9 |
| **R-9** | **Stack exhaustion.** Recursive drop of deep `Box` trees and lists. 16 KiB kernel stacks shared with IRQs. Large by-value structs | Medium | High (kernel: corruption/panic; user: crash) | Per-value size limits. Kernel frame (2 KiB) and chain checks. Recursion requires `@unboundedStack` in the kernel. Library `drop` for recursive types uses iterative destruction (explicit worklist). **Status (M3c):** compiler drop glue iterates over a box's *tail* (type-system.md §18.5), so lists of any length are destroyed in constant stack. `deep-structures.nova` (3 × 200,000 nodes) crashes with recursive glue at `-O0` and passes with the loop. Trees still recurse along non-tail children: balanced trees are fine, left-degenerate ones are not (open for the kernel profile, C4) | `-fstack-usage` reports. Deep-structure run-pass tests | M3, C4 |
| **R-10** | **Expressiveness gap drives `unsafe` use.** v0 forbids references in structs (E3), so users write `unsafe`, which erodes the guarantee | High | Medium | Ship safe alternatives early: `Span` indices, `SlotMap` (M6e: handles can be stored in structs and collections), arenas. OD-3 is implemented (M6x, `type-system.md` §25): structs, enums and collections may hold references with region parameters, so zero-copy parsers and arena graphs need no `unsafe`. Track `unsafe` density per package. M8a: `unsafe` exists, and every use needs a `Safety:` contract (N0283), which keeps it visible in review | `unsafe` audit report in `novac` | M6, M8 |
| **R-11** | **Moved or uninitialised C state.** Kernel C state can point into itself once initialised (an empty list head; a mutex's wait queue), so a bitwise move corrupts it; C state used before its init runs misbehaves (a zeroed spinlock's owner is CPU 0) | Medium | Critical | C-laid-out values are made only in place, by a literal given to `Box.create`/`createIn`, never moved (every move is N0294), and `@placed` methods run the C initialisers at the final address before any code can see the value (C7b, type-system §33) | `check-fail/c-state-moves.nova`; `ffi/embedded.nova` checks in C that self-pointing list heads survive in their boxes | C7 |
