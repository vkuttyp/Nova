Status: **in progress** (started 2026-10-23; 7a–7d done). Normative: `c-backend.md` (§3 control flow, §7
debugging, §8 validation), `intermediate-representation.md` §5 (the NIR interpreter), `testing.md`

## Acceptance criteria (`roadmap.md`)

1. A 24-hour fuzz campaign with no miscompile across clang/GCC × O0/O2.
2. The interpreter agrees with native output on the whole run corpus (run-pass and run-fail), and
   with the fault-injection sweep's outcomes.
3. Source maps: a debugger's line table maps generated code to Nova lines; generated C contains no
   host paths, with or without directives.
4. Structured C: the run corpus passes with structured and flat C under every C configuration;
   reviewed snapshots show the structured form.
5. MSVC best-effort: the hosted run corpus compiles with MSVC (C11) in CI, and runs where the
   runtime supports Windows; unsupported parts are listed.
6. Docs: `c-backend.md`, `intermediate-representation.md`, `testing.md`, `roadmap.md`, `risks.md`
   (R-1, R-3).

## Results so far

| Increment | Evidence (run 2026-10-23) |
|---|---|
| 7a | `SourceMapTests`: clang's line table (`-g -S`, `.file`/`.loc`) for a two-function program names `demo/gcd.nova` and every statement line (1–7, 9, 12–15), and no line outside the file or on the blank line; the `main.c` hand-back numbers are exact; directives are deterministic and contain no host path for all run-pass programs; `SourceText.SourcePath` cases. The run corpus gained a configuration `clang -O0 -g line-directives` (every run-pass and run-fail program builds warning-clean and agrees). Snapshot `emit-c/line-directives.c` reviewed. Manually: `novac build -g run-pass/gcd.nova`, then `lldb -o "breakpoint set --file gcd.nova --line 5"` stops in `nv_gcd` at `gcd.nova:5`, lists the Nova source, shows `v_x_2 = 1071`, and the backtrace names `gcd.nova:13` for the caller. Default output (no directives) is byte-identical to before: the 17 existing C snapshots are unchanged, so the guest runs (`c2.py`, `c3.py`) were not repeated. Not done: columns (C's columns, not Nova's, appear in the line table; `#line` cannot carry columns) |
| 7b | Structured form is the default; `--flat-c` (and `CEmitOptions.Structured = false`) keeps the flat form. The run corpus (run-pass and run-fail) passes under every configuration in the structured form and in a `clang -O2 flat` oracle configuration; `-Wimplicit-fallthrough` joined the strict warning set. `StructuredCTests`: for every run-pass program, every NIR statement and exit appears exactly once in the tree and every remaining `goto` names a label in the tree; a nested-loop function needs no `goto` (3 `break`s); a diamond becomes `if`/`else`; an irreducible graph (built by hand, since Nova source cannot produce one) falls back to flat. Over the 137 run programs, `goto`s inside functions drop from 1,188 (flat) to 28, in 15 programs: the rest are exits that C cannot express structurally (e.g. leaving a loop from inside a `switch`). The flat snapshot (`emit-c/flat.c`) equals the earlier output; the 14 structured snapshots were reviewed. Guest runs (structured C is now what runs in CosmoOS): `c2.py` (137/137 programs, 228/228 sweep runs) and `c3.py` (26/26 BusyBox cases, `c3-io`) pass in QEMU on x86-64 and on the CosmoOS VM on AArch64. The AArch64 runs were repeated on the final code; the x86-64 runs may have used the build from just before the elimination fixpoint, which changes one `goto` into a `break` in one corpus program |
| 7c | `novac run --interp` (`src/Nova.Compiler/Interpreter/`): byte-addressed memory with the target layout, runtime algorithms step for step, host C library for files and sockets. `InterpreterTests`: all 137 run-pass and run-fail programs give the corpus expectations (stdout, exit status, the exact panic line, empty stderr otherwise). The fault-injection sweep compares the interpreter with the native ASan build at the baseline and at every failure point (programs with ≤ 200 attempts; 30 spread points above that): all 103 sweep tests agree, so attempt counts, outcomes and the `NOVA_ALLOC_REPORT` line are equal. The collection property tests (24 programs) agree with their models in the interpreter. `c3-io` (files, loopback TCP, `Process.run`) and `nwc` on the 17 recorded BusyBox cases agree in the interpreter. The safety oracle catches three unsafe NIR mutations: a duplicated box drop ("double free"), a read after `StorageDead` ("use of a dead local") and, without its bounds check, a read past a vector's length ("use of uninitialised memory", where native C prints garbage). Found while building it: nothing in the compiler; the interpreter's own first bugs were a stable vector's `length` offset (256, after the chunk pointers) and descriptor-sized results. Speed: `deep-structures` (600,000 allocations) takes 2.3 s in a Release build. Not done: borrow tracking (Stacked Borrows); Windows I/O |
| 7d | `tests/Nova.Fuzz` (generator, oracle, campaign tool; testing.md §5). Programs of 200–750 lines that call every function and print 20–100 checksum lines; about 8% panic through a raw operation, so panic paths are compared too. The checker accepts 5,000 of 5,000 generated programs. `FuzzTests` runs 32 seeds through the whole oracle in the suite. **Findings, all fixed, each with a corpus test:** (1) C name collision: a Nova function `add_i32` became `nv_add_i32`, the runtime's checked add; top-level functions are now `nvF_<name>` and the C namespaces are specified (c-backend §2.1; `run-pass/runtime-names.nova`). (2) Checker false positive: `v.push(p.a)` through a `borrow mut` parameter was N0272, because a write's carriers were taken from the operand's base local whatever its type; only values whose type may hold loans carry loans now (`run-pass/copies-through-parameters.nova`; every compile-fail test still reports its error). (3)–(6) Generated C that was not warning-free for valid Nova: `x = x` (`-Wself-assign`), `a == a` (`-Wtautological-compare`), a constant index past an array's end after its panicking check (`-Warray-bounds`), and in the structured form a label before statements that print nothing (`-Wc23-extensions`) (c-backend §5; `run-pass/warning-free.nova`, `run-fail/constant-index-past-end.nova`; the label case is covered by fuzz seed 1). Campaigns on macOS (Apple clang; no GCC on this host): 2,000 programs (seeds 1–2000, 7 min 23 s, 8 jobs, raw-operation rate 3%) with 0 findings after the fixes, 34% of them panicking; with the rate lowered to 1%, 500 programs (seeds 5000–5499) with 0 findings and 9% panicking. GCC configurations run in Linux CI through `FuzzTests` and in the 7e campaign |
